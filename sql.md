# Supabase SQL Editor setup

Open the Supabase project's SQL Editor, paste the complete script below, and run it once. It is safe to run again; existing tables are left unchanged.

```sql
create table if not exists public.admins (
  id integer generated by default as identity primary key,
  username text unique not null,
  pass_hash text not null
);

create table if not exists public.teams (
  id integer generated by default as identity primary key,
  number text unique not null,
  name text not null,
  remarks text default ''
);

create table if not exists public.rounds (
  id integer generated by default as identity primary key,
  name text not null,
  max_marks double precision not null check (max_marks > 0),
  status text not null default 'active',
  position integer not null default 0
);

create table if not exists public.scores (
  team_id integer not null references public.teams(id) on delete cascade,
  round_id integer not null references public.rounds(id) on delete cascade,
  marks double precision not null check (marks >= 0),
  primary key (team_id, round_id)
);

create index if not exists scores_round_id_idx on public.scores(round_id);

create table if not exists public.score_history (
  id integer generated by default as identity primary key,
  team_label text,
  round_label text,
  old_marks double precision,
  new_marks double precision,
  admin text,
  at text default to_char(now() at time zone 'utc', 'YYYY-MM-DD"T"HH24:MI:SS"Z"')
);

create table if not exists public.settings (
  key text primary key,
  value text
);

alter table public.admins enable row level security;
alter table public.teams enable row level security;
alter table public.rounds enable row level security;
alter table public.scores enable row level security;
alter table public.score_history enable row level security;
alter table public.settings enable row level security;
```

## Application connection

Set `DATABASE_URL` in the Node server's private environment to the Supabase PostgreSQL connection string with `sslmode=require`. If the password contains URL-reserved characters, URL-encode it first. Do not put the database connection string or database password in frontend code or commit it to source control. Configure `JWT_SECRET`, `ADMIN_USER`, and `ADMIN_PASSWORD` as described in `.env.example`.

The app connects directly to PostgreSQL from its server and does not use the Supabase publishable key. Row-level security is enabled without client policies so the tables are not available through the Supabase client API; the trusted server connects directly as the database owner. Do not use the publishable key as a database password.

To migrate data from the previous SQLite version, download its JSON backup before deploying this version, then restore it from the admin Dashboard after the new server is running. The app updates PostgreSQL identity sequences when restoring explicit IDs.
